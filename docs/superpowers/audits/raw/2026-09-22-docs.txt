## RS3-01 [확정] baselines.py 의 순위 상관이 행 순서에 따라 ±1 이 된다
파일: src/investment_agent/research/models/baselines.py:155-161 (_rank_correlation)
코드:
  a = np.argsort(np.argsort(actual)).astype(float)
  p = np.argsort(np.argsort(predicted)).astype(float)
  if np.std(a) == 0 or np.std(p) == 0: return 0.0

문제: argsort(argsort(x)) 는 동률을 "등장 순서"로 갈라 서로 다른 정수 순위를 준다.
      따라서 예측이 전부 같은 값이어도 p = [0,1,2,...,n-1] 이 되고 np.std(p) != 0 이다.
      즉 함수가 스스로 둔 std==0 가드에 **도달할 수 없다**. 주석/가드가 의도한 답(0.0)과
      실제 답이 다르다 — 어느 쪽이 틀렸는지는 가드가 말한다(가드가 의도다).

수치 재현 (numpy):
  actual=[-0.05,-0.01,0.0,0.02,0.07], predicted=[0.006]*5
  -> 0.99999999   (actual 오름차순)
  -> -0.99999999  (actual 내림차순)
  -> -0.20        (actual 뒤섞음)
  scipy.stats.spearmanr 의 정답: nan (정의되지 않음)
  std of ranks for constant pred: 1.414 (0 이 아니다 -> 가드 무력)

영향: `naive` baseline 은 정의상 상수(train 평균)를 예측한다. 따라서 naive 의
  out_of_sample.rank_correlation 은 **표본 행 순서가 정하는 값**이고, naive 는
  challenger 비교의 기준선이다. 동률이 많은 label(0 이 많은 구간)도 같은 방식으로 오염된다.
  표시 경로: dashboard/components/alpha_lab.py:159 "OOS 순위 상관".
  저장 경로: ModelArtifact.to_db_record -> trading.model_versions.params.out_of_sample.

전에: def _qtrs(value) -> int:  except (TypeError, ValueError): return 0
0 은 이 도메인의 **실제 값**이다(0=instant, 1=분기, 4=연간). 그래서 못 읽은 것과
"시점값이다"가 같은 값으로 접힌다. 결과 경로:
  :149  _period_is_usable(period_kind, 0) -> True  (0 은 annual·quarter 양쪽에서 usable)
  :154  belongs_to_report_period(..., is_instant=True)
  :177  period_start = None
  :209  is_instant = True
  :210  period_kind = "instant"
즉 3개월 흐름(매출)이 시점의 잔액처럼 라벨링된다.
같은 파일의 다른 필드는 전부 못 읽으면 None 을 주고 호출부가 continue 한다
(_to_number, _int_to_date, period_end/filing_end). _qtrs 만 규약을 깼다.
현실적 발동 조건: SEC num.txt 의 qtrs 가 빈칸이면 pandas 가 NaN 으로 읽고 int(nan) -> ValueError.
  키가 없으면 None -> TypeError. 둘 다 옛 코드에서 0 이 됐다.
수정: _qtrs -> int | None, None 이면 _period_is_usable 의 `in` 검사가 걸러 행을 버린다.
검증: 새 테스트 2개(UnreadableQuarterCountTest).
  - qtrs=1 은 여전히 흐름(is_instant=False, period_start="2026-03-30")
  - qtrs in (None, "", "N/A", nan) 은 전부 버려진다(subTest 4개)
  주입(return 0 로 되돌림) -> 4개 subTest 전부 "Lists differ: [{...}] != []" 실패 확인.
운영 영향 규모는 **측정하지 못했다**: is_instant·period_start 는 application 메모리에만 있고
  fundamentals.segment_metrics 에 저장되지 않는다(CLAUDE.md 규칙 6). 따라서 과거에 이 경로로
  잘못 분류된 행이 몇 개인지 Postgres 로는 셀 수 없다. 지금 코드가 옳은 쪽으로 바뀐 것만 확실하다.
