### [RR2-01] 적자·현금소진 기업은 value factor category가 통째로 빠져 종합점수가 오히려 올라간다  [확정] [높음] [정확성]
- 파일: src/investment_agent/research/factors/core.py:41-58,184-196 / src/investment_agent/research/valuation/engine.py:229-251
- 증상: 적자(PER 없음)·음의 FCF 기업은 value category의 3개 factor 중 2개가 결측이 되고,
  `len(parts)/len(members) = 1/3 < _MIN_CATEGORY_COVERAGE(0.5)`라서 value category 점수가 아예 만들어지지 않는다.
  composite은 "있는 category의 가중평균"이므로 value가 빠지면 **나쁜 점수를 안 받는 것이 아니라 평균에서 제외**되어
  종합점수가 올라간다.
- 근거:
    engine.py: `if inputs.free_cash_flow_ttm.value <= 0: reasons.setdefault("fcf_yield", "…_nonpositive")`  (fcf_yield=None)
               `result["valuation_earnings_yield"] = 1.0 / pe if pe is not None and pe > 0 else None` (layer.py:262)
    core.py:   `if parts and len(parts) / len(members) >= _MIN_CATEGORY_COVERAGE: category_scores[ticker][category] = …`
               `composite = math.fsum(weight * value for …) / weight_sum`
- 재현(구체 숫자): 동일가중 6 category. 흑자 저평가주 A가 quality/balance/growth/revision/momentum 각 0.5,
  value 0.9 → composite 0.567. 적자주 B가 같은 5개 0.5, value는 ps_ttm만 남아 category 탈락 → composite 0.500.
  반대로 B의 value를 실제 랭크로 넣으면(earnings_yield·fcf_yield 최하위 → 약 0.1) composite 0.433이 된다.
  즉 적자 때문에 **0.433 대신 0.500**을 받는다. 후보 상위 N 컷에서 순위가 뒤집힌다.
- 원인: "결측은 그 factor에서 빠질 뿐 0점을 받지 않는다"(모듈 docstring)는 규칙이 *공시가 늦은* 결측을 위한 것인데,
  적자·자본잠식·음의 FCF는 결측이 아니라 **나쁜 관측**이다. 원장이 그 둘을 같은 None으로 접는다
  (engine.py가 `*_nonpositive` 사유를 남기지만 feature 계층은 사유를 보지 않는다).
- 해결: (a) 비율 대신 부호가 살아 있는 형태를 feature로 쓴다 — earnings_yield = earnings_ttm/market_cap,
  fcf_yield = fcf_ttm/market_cap (둘 다 음수 허용, market_cap>0만 요구). 이러면 적자는 최하위 랭크를 받고
  결측(미공시)과 구별된다. (b) 그때까지의 완화책은 `missing_reasons`에 `*_nonpositive`가 있으면
  value 랭크를 관측된 최하위로 두는 것.
- 위험: 후보 선정 순위가 바뀐다. FEATURE_VERSION 승격 대상(원장에 음수 yield가 새로 생김).

### [RR2-06] 사후평가·RL 보상의 총수익률이 분할을 두 번 반영한다 — 4:1 분할 구간에서 +300% 가짜 수익  [확정] [높음] [정확성]

  "종가(USD, 분할 조정, 배당 미조정)", 수집기 `yahoo.py:30 auto_adjust=False` — yfinance는 분할만 back-adjust).

  확정 전까지는 배당도 `shares` 곱 없이 더한다. 회귀 테스트는 분할이 든 구간에서 수익률이
  분할 비율과 무관함을 검사한다(현재 테스트에 그런 케이스가 없다).
- 위험: 이미 저장된 `decision_experiences`·평가 원장의 분할 구간 행이 오염됐다. RL·판단 성과 주장에

  그 몇 건이 정확히 꼬리값이라 보상 학습·성과 요약에서 가장 큰 가중을 받는다.

  `experiment.RLPolicyEvaluation`은 `-drawdown`(음수)으로 담는다. 승격 게이트는 음수를 전제한다:
  `if summary.max_drawdown < -self.criteria.max_drawdown` (양수는 절대 걸리지 않는다),
  `if … drawdown > 0 … : data_integrity_incidents += 1` (양수는 데이터 오류로 센다).
- 근거:
    environment.py:234  `drawdown = max(0.0, 1.0 - self.nav / self.peak_nav)`
    pipeline.py:153     `max_drawdown=float(max((info["drawdown"] for info in infos), default=0.0))`
    experiment.py:54    `max_drawdown=-drawdown,`
    gate.py:290         `if excess is None or drawdown is None or drawdown > 0 or …: data_integrity_incidents += 1`
- 재현: 낙폭 25%인 정책을 `pipeline` 경로로 평가하면 `max_drawdown=0.25`.
  게이트의 한도 검사 `0.25 < -0.20`은 거짓이라 **한도를 지나가고**, 동시에 정합성 검사에서
  `0.25 > 0`이라 오류 1건으로 세어 승격이 다른 이유로 막힌다 — 어느 쪽도 "낙폭이 크다"고 말하지 않는다.
  `experiment` 경로로 평가한 같은 정책은 `-0.25`로 올바르게 걸린다.
- 원인: 부호 규약이 한 곳에 선언돼 있지 않다. 생산자가 셋, 소비자가 하나다.
- 해결: `info["drawdown"]`(비음수)와 원장 컬럼(`max_drawdown`, 음수)의 의미를 각각 이름으로 갈라
  (`drawdown_fraction` / `max_drawdown`) 변환을 한 함수에만 둔다. 게이트는 부호를 검사하지 말고
  절대값 한도로 판정하거나, 잘못된 부호를 조용히 오류로 접지 말고 거절 사유로 드러낸다.
- 위험: 현재 `portfolio_evaluations` 생산자가 없어(RS-15) 사용자에게 가는 숫자는 없다.
  생산자가 붙는 순간 낙폭 한도가 조용히 무력화된다.

### [RR2-16] RL 학습·추론은 결측 feature를 0으로 채운다 — layer가 금지한 규칙이고 log 스케일 열에서는 극단값이 된다  [확정] [중간] [정확성]

- 증상: `features[t, i, j] = 0.0 if value is None else float(value)` — 결측을 0으로 채운다.

  `features/layer.py:361`의 docstring은 0 채움을 명시적으로 금지한다

- 재현: `valuation_market_cap_log`의 정상 범위는 log(2e9)≈21.4 ~ log(4e12)≈28.9다. 결측이면 0이 들어가

- 원인: 두 학습 경로가 같은 feature 계약을 다른 규칙으로 행렬화한다. `__is_missing` 열이 있어
  이론상 구별은 가능하지만, 값 자체가 분포를 흔드는 것은 그와 별개다.
- 해결: RL도 `impute_cross_section`(같은 as_of 단면 중앙값)을 쓰거나, 최소한 log·수준 스케일 열에
  대해 0이 유효 범위 밖임을 검사한다. 운영 경로(`decision_training_set`)는 결측이 없으므로
  현재 영향은 `load_training_set` 경로(fallback)에 한정된다 — 그 경로가 실제로 쓰이게 되는 시점의 함정이다.
- 위험: RL은 challenger 전용이라 실계좌에 직접 닿지 않는다. 정책 비교 결과의 해석이 달라진다.

### [RR2-17] 판단 한 종목의 가격 경로가 어긋나면 RL 재학습 전체가 예외로 선다  [확정] [중간] [구조]
- 파일: src/investment_agent/research/rl/decision_dataset.py:61-63
- 증상: 같은 시점의 판단 경험들이 `end_trade_date`와 `benchmark_return`을 **정확히 하나씩만** 가져야 한다.
  `build_decision_experiences`는 종목별로 `dates = sorted(set(asset_path) & set(spy_path))`의
  교집합으로 구간을 잡으므로, 어느 한 종목에 봉이 하나 빠지면 그 종목의 `end_trade_date`·
  `benchmark_return`이 달라지고 `decision_training_set`이 `ValueError`로 전체 학습을 세운다.
- 근거:
    decision_dataset.py: `if len(horizons)!=1 or len(benchmark)!=1: raise ValueError("inconsistent decision label horizons")`
    build_decision_experiences.py:53-56: `dates = sorted(set(paths[0]) & set(paths[1]))`
      `asset = total_return([paths[0][key] for key in dates], horizon_days)`
      `benchmark = total_return([paths[1][key] for key in dates], horizon_days)`
- 재현: 같은 날 판단한 A·B 중 A가 거래정지로 하루 봉이 없으면 A의 20거래일 종료일이 B보다
  하루 뒤가 되고, SPY 교집합도 달라져 `benchmark_return`이 미세하게 다르다(부동소수 집합 비교라

- 원인: 종목별로 계산한 벤치마크를 시점 단위 스칼라로 접으면서 완전 일치를 요구한다.

- 해결: 벤치마크 구간을 SPY 자체 거래일로 시점당 한 번 계산해 모든 종목이 같은 값을 쓰게 하고,

- 위험: 낮음(값이 아니라 가용성). 현재 실패가 나면 로그에만 남고 후보가 조용히 안 생긴다.

### [RR2-18] 순위 상관을 세 가지 서로 다른 동점 규칙으로 계산한다  [확정] [낮음] [구조]

### [RR2-19] 변동성이 0인 수익률 시계열이 DSR 검정을 통과한다  [의심] [낮음] [정확성]
- 파일: src/investment_agent/research/evaluation/deflated_sharpe.py:246
- 증상: `std_r = math.sqrt(var_r) if var_r > 1e-12 else 1e-6` — 표본 분산이 0이면 표준편차를
  1e-6으로 **대체**한다. 매 구간 수익률이 동일한(분산 0) 양수 시계열은 기간 샤프가 1,000이 되고
  DSR 확률이 1.0으로 나와 `is_statistically_significant=True`가 된다.
- 근거: 위 한 줄. 이어지는 `period_sr = mean_r / std_r`와 `z_stat = (period_sr - exp_max)/se_sr`.
- 재현: `returns = [0.001] * 20` → var=0 → std=1e-6 → period_sr=1000, skew=0·kurt=3(std>1e-6이 거짓이라
  기본값), var_sr=(1+0.5·1e6)/19≈26,316, se≈162, z≈6.2 → probability≈1.0 → 통과.
  이것이 RL challenger 승격의 유일한 과적합 방어(`min_dsr_probability=0.90`)다.
- 원인: 분산 0을 "아주 작은 분산"으로 바꿔 계산을 계속한다. 분산 0은 샤프가 정의되지 않는 상태다.
- 해결: `var_r <= 1e-12`이면 `n < 5`와 같은 취급(확률 0.0·`is_statistically_significant=False`)으로
  fail-closed하고 사유를 남긴다.
- 위험: 현재 환경에서 완전 상수 수익률이 나오는 경로를 확인하지 못해 [의심]으로 둔다
  (전량 현금 정책은 비용 때문에 상수 **음수**가 되어 통과하지 않는다).

### [RR2-20] 사건 `novelty`가 `source_diversity`와 수학적으로 동일한 값이다 — "새로움"을 재는 feature가 없다  [확정] [중간] [정확성]
- 파일: src/investment_agent/research/features/event_intelligence.py:260,271
- 증상: 두 값이 같은 식이다.
    source_diversity = len(providers) / source_count
    novelty          = min(1.0, 1.0 / max(1.0, source_count / max(1, len(providers))))
  `providers`는 항상 cluster의 부분집합이라 `source_count / len(providers) >= 1`이고
  `max(1.0, ·)`는 그 값을 그대로 통과시킨다. 따라서 `novelty == len(providers)/source_count == source_diversity`가
  **모든 입력에서** 성립한다. `Event.novelty`·`EventFeatureSnapshot.novelty`가 독립 feature로 저장되고
  학습·프롬프트가 "새로움"으로 읽지만 실제로는 출처 다양성의 사본이다.
- 근거: 위 두 줄. 반례를 만들 수 없다(`len(providers) >= 1`, `source_count >= len(providers)`).
- 재현: 3개 기사·2개 provider → source_diversity = 2/3 = 0.667, novelty = 1/max(1, 3/2) = 1/1.5 = 0.667. 동일.
  1개 기사·1개 provider → 둘 다 1.0.
- 원인: novelty를 "같은 사건을 몇 번 다시 말했나"로 정의하려 했으나 식이 다양성으로 환원된다.
  실제 새로움은 **직전 window에 같은 cluster가 있었는가**(과거 사건과의 유사도)로 재야 하며
  `cluster_contents`가 그 정보를 갖고 있는데 쓰지 않는다.
- 해결: novelty를 "이 cluster의 토큰 집합이 직전 window의 어느 cluster와도 임계 미만으로 겹친다"로
  다시 정의하거나, 중복 feature임을 인정해 제거한다(제거는 feature 계약 변경).
- 위험: `EventFeatureSnapshot.novelty`를 소비하는 학습·요약의 값이 바뀐다. 현재는 두 열이 완전 상관이라
  선형 모델에서 계수가 임의로 갈리고(다중공선성) 트리에서는 한쪽만 선택된다.
