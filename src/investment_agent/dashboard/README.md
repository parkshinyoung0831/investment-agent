# Dashboard — ATLAS 읽기 전용 투자 터미널

이 디렉터리는 Discord 알림과 동일한 운영 사실을 **읽기 전용**으로 탐색하는
Streamlit 관제 화면이다. 대시보드는 Supabase 행을 생성·수정·삭제하지 않으며,
Discord 메시지 발송, 승인 상태 변경, Toss 주문 생성·수정·취소를 제공하지 않는다.

## 시각 시스템

대시보드는 저장소의 `DESIGN-system.md`를 따른다. 토스의 이해하기 쉬운 정보 계층과
Toss Blue를 기본 시각 언어로 쓰고, 금융 값의 상승·하락에만 Coinbase 계열의 초록·빨강을
쓴다. 상승은 항상 좋은 상태, 하락은 항상 나쁜 상태를 뜻하지 않는다. 부호·라벨·문장을
함께 보여 방향과 해석을 분리한다.

- Streamlit 네이티브 `theme.light`와 `theme.dark`를 모두 제공한다.
- 내비게이션과 운영 상태는 사이드바에 모으고, 본문은 `현재 판단 → 중요한 변화 → 근거`로 읽힌다.
- 모든 워크스페이스는 같은 제목, 읽기 전용 상태, Discord 대응, 출처 도움말 순서를 쓴다.
- 차트는 현재 테마의 시맨틱 토큰을 읽으며, 무지개 팔레트나 넓은 등락색 면을 쓰지 않는다.
- 카피는 해요체와 원인·다음 행동을 함께 말하는 Navigating Error 원칙을 쓴다.

## 적응형 정보 구조

각 워크스페이스는 `요약 → 단일 선택 → 상세` 순서로 동작한다. 첫 화면에는 현재
판단에 필요한 상태와 경고만 두고, 카드나 segmented control로 선택한 한 영역만
차트·근거·원자료를 렌더링한다. 숨겨진 상세 뷰는 계산하지 않는다.

첫 화면은 **판단에 필요한 사실을 전부** 보여준다. 접는 것은 '더 깊은 근거'이지
'기본 정보'가 아니다 — 화면을 열자마자 빈 껍데기가 보이면 쓸 수 없는 화면이 된다.

| 워크스페이스 | 첫 화면 | 클릭하면 |
|---|---|---|
| 매크로 시황 | 레짐 판정(근거·반대 신호) · 공포탐욕/VIX · 경보 32개 분류 · **전 지표 카드 4섹션** | 그 지표 하나의 전 구간 시계열·파생 지표·관측 원자료 |
| 지표 발표 | 향후 7일/전체 예정 · 발표 완료 · 서프라이즈 수 · 발표 카드 | 그 발표의 예상 이력(기관·시점별)과 실제값 개정 이력 |
| 실적 | (결과) 공시 카드 한 장 — 등급·매출/이익·마진·현금·시장 기대 | 실적·현금흐름 / 가격·밸류 / 건전성 / 기술·주주환원 / 세그먼트 / 원자료 |
| 13F | **매니저 7명 카드** — 보고 가치·종목 수·상위 3종목·공시 지연 | 그 매니저의 포트폴리오 도넛·보유 표 / 분기 변화 / 공시 장부 |
| 시세·지표 | **전략 6개 카드** — 이번 달 모드와 배분 막대 · 전체 백테스트 | 그 전략의 장기 백테스트 / DB 적재 구간 / 월별 판단 / DB 대조 / 경로 추정 |
| 판단 과정 | 5단계(종목 판단→포트폴리오→위험 심사→실행 의도→주문) 건수 | 그 단계의 원장 기록 |
| 주문·체결 | 실행 경계 상태 · Intent/승인/주문/체결 건수 | 주문·체결 / TCA / 정산 · **AI 승인 검토**(접힘) |
| 모델·학습 | 하네스 잡 상태 · PPO 챔피언 검정 | **투자 엔진(Alpha Lab)** 탭 |
| 보유·계좌 | 저장된 계좌 스냅샷 상태 | 최신 스냅샷 요약·보유·리밸런싱·리스크 |
| 시스템 | 프로세스 요약 | 자동화 잡 / 단계 상세 / Ops 이력 |

숨긴 상세는 **코드 실행 자체가 되지 않는다.** 외부 조회(뉴스)와 무거운
계산(백테스트·Monte Carlo)은 해당 화면 진입 또는 실행 버튼 이후에만 돈다.


### 사이드바는 세 갈래다

가진 데이터 / 내 돈 / 그 둘을 잇는 판단. 홈과 시스템만 단독으로 둔다.

```text
홈
가지고 있는 데이터 : 매크로 · 지표 발표 · 실적 · 13F · 시세·지표
내 포트폴리오      : 보유·계좌 · 주문·체결
투자·매매 로직     : 판단 과정 · 모델·학습
시스템
```

**빈 화면에는 왜 비었는지 적는다.** 그냥 비워 두면 코드가 죽은 것과 아직 안 쌓인 것을
화면만 보고 구분할 수 없다 — `ui.awaiting_data()`가 무엇이 없는지와 언제 채워지는지를
함께 적는다. Research 데이터가 아직 없는 경우에는 "아직 적재되지 않음"을 명시하고,
연결 실패·지원하지 않는 기능·정상적인 빈 결과를 서로 다른 상태로 표시한다.

### 상세를 여는 방식은 고를 수 있다

같은 상세라도 화면 폭과 작업 방식에 따라 나은 자리가 다르다. 사이드바에서 고르며,
어느 방식이든 **선택 전에는 렌더도 계산도 하지 않는다**는 규칙은 같다.

| 방식 | 자리 | 언제 |
|---|---|---|
| `창` (기본) | 모달 창 | 목록 위치를 잃지 않고 하나만 깊게 볼 때 |
| `아래` | 목록 아래 | 인쇄·스크롤 캡처로 통째로 남길 때 |
| `옆` | 목록 옆 고정 | 여러 항목을 번갈아 비교할 때 |

### 선택은 카드 클릭만이 아니다

목록을 **그림으로 바꿔 클릭**할 수 있다. 클릭 선택과 카드 버튼은 같은 세션 상태를
쓰므로 어느 쪽으로 골라도 같은 상세가 열린다.

- 매크로 `지도 · 오늘 움직임` — 전 지표를 직전 관측 대비 변화율로 세운 가로 막대.
  모든 지표가 갖는 값이라 32개를 한 축에 세울 수 있다. 막대 색은 경보 등급.
- 매크로 `지도 · 52주 위치` — x축 저점 대비, y축 고점 대비 산점도. 52주 고저가
  계산된 지표만 올리고, bp 기준인 금리·스프레드는 올리지 않는다(빈 점을 만들지 않는다).
- 13F 포트폴리오 도넛 — 조각을 클릭하면 그 종목의 보유 상세. 보유 표의 행 선택도 같다.
- 퀀트 전체 백테스트 곡선 — 곡선의 점을 클릭하면 그 전략의 상세가 열린다.

### 매크로와 지표 발표는 분리한다

`macro`는 연속 관측(시세·금리·환율)과 시점이 정해진 사건(발표)의 단일 owner다.
화면은 `reporting` read model을 통해 두 종류를 나눠 표시하며 domain 표를 직접 조립하지 않는다.

매크로 지표 집합·파생 계산·임계 판정은 **Discord 알림과 같은 순수 함수**를 쓴다
(`investment_agent.reporting.services.macro`의 `constants.CORE_LAYOUT`, `metrics.compute_metrics_series`,
`thresholds.eval_row`, `format.meta_tags`). ETL은 raw만 저장하므로 z·이동평균·52주
고저는 화면이 그때 계산하며, 카드와 화면이 서로 다른 숫자를 말하지 않는다.
등락 색 방향도 같은 SSOT를 쓴다 — `constants.INVERSE_SERIES`(VIX·MOVE·HY_SPREAD)는
올라가는 것이 나쁜 지표라 상승을 하락색으로 칠한다.

### 13F 비중은 '보고된 장부 안에서의 비중'이다

13F는 분기말 long equity만 담는다. 숏·파생·채권·해외 상장·비상장은 애초에 들어오지
않고 제출까지 최대 45일 걸린다. 그래서 도넛의 비중은 매니저 자산 전체의 배분이 아니며,
화면은 이 한계를 상시 표시한다. 금액을 읽지 못한 행은 0으로 채우지 않고 비중 계산에서
빼고 그 개수를 밝힌다.

### 저장된 사실과 화면 계산을 섞지 않는다

두 가지가 **서로 다른 사실**이라서 화면에서도 분리해 둔다.

| 구분 | 무엇 | 기간 | 어디서 |
|---|---|---|---|
| Research 저장 배분 | 운영 ETL이 월 1회 적재한 로컬 DuckDB 배분 | 적재를 시작한 달 이후 | 퀀트 `요약`·`성과`·`이력` |
| 룰 재현 백테스트 | 같은 전략 함수를 월말마다 다시 돌린 결과 | 월말 종가가 있는 전 구간 | 퀀트 `룰 재현 백테스트` |

로컬 Research 배분에는 운영이 실제로 돌린 달만 있어 백테스트 구간이 짧다. 룰 자체는
월말 종가만 있으면 과거로도 재현되므로, `룰 재현 백테스트`가 `investment_agent.research.strategies.catalog`의
**같은** 계산 함수(`compute_one`)를 월말마다 호출해 walk-forward로 이어 붙인다.

- 월말 M까지의 종가만 보고 배분을 정하고, 실현 수익률은 다음 달 M+1로만 매긴다(look-ahead 없음).
- 적용월은 운영 `decision_and_apply_dates`와 같은 규칙(결정 월말 + 1일 → 그 달 1일)을 쓴다.
- 필요한 자산의 월 수익률이 없으면 그 달을 0으로 채우지 않고 `제외된 달`에 사유와 함께 남긴다.
- `DB 대조`가 같은 적용월의 저장 배분과 재현 배분을 맞춰 보고 어긋난 달만 드러낸다.
- 결과는 `st.session_state`에만 있고 DB에 저장하지 않는다. 전략·가격 기준이 바뀌면 폐기한다.
- `catalog.py`에 계산 함수가 없는 전략 id는 재현하지 않고 그 사실을 표시한다.

### 실적은 Discord 카드를 재현하고, 그 위에 확장한다

`Discord 카드 전체`는 알림과 **같은** 규칙의 재현이고, `확장 분석`은 카드가 지면 때문에
싣지 못하는 것을 더 본다. 두 보기는 loader가 분리돼 있어 서로의 SELECT를 실행하지 않는다.

| 확장 섹션 | 읽는 것 | 카드와의 차이 |
|---|---|---|
| 확장 섹션 | 읽는 것 | 카드와의 차이 |
|---|---|---|
| 종합 재무·성장·마진 | `fundamentals.financials` + application 계산기 | 카드와 같은 원장으로 TTM·마진·성장 지표를 계산 |
| 특수 계정 재무 | `fundamentals.financials` 실제 저장 필드 | 카드에 아예 없는 은행 NII·충당금·예금 등 특화 계정 |
| 기술 지표 | 로컬 `feature_signals_daily` | 카드는 공시 시점 스냅샷, 여기는 저장된 RSI·MACD 시계열 |
| 세그먼트 전 축 | `segment_metrics` 전체 | 카드는 종류별 대표 축 1개·상위 6행·기타 합산, 여기는 모든 축·모든 멤버·다기간 추이·세그먼트 자산 |
| 수집·발송 감사 | terminal `fundamentals.filing_processing` + `notification_outbox` + Discord/GitHub 운영 로그 | 카드에 없음. 성공 provenance·실제 Discord 발송 여부와 실패 원인 확인 경로 |

세그먼트 품질 게이트는 카드와 같다 — `verified`/`partial`이 아닌 값은 숫자로 만들지 않고
상태 문자열로만 남기며 차트에 올리지 않는다. 비중 분모도 게이트를 통과한 매출만 쓴다.

발표 예정 보기의 조회 창은 `지난 7일 + 향후 21일`(기본) / `이번 주 (Discord 규칙)` /
`향후 90일` 중에서 고른다. Discord 카드는 '이번 주(월–일)'만 주장하므로 그 규칙을
선택지로 남기고, 나머지 창은 (종목, 추정 기간)별 최신 스냅샷을 남겨 다음 분기까지 본다.
등급(shifted/stale/estimated)·전년 제출일 규칙은 세 창 모두 `reporting.earnings.schedule`의
같은 순수 함수를 쓴다.

### 퀀트 용어

- **장기 백테스트** — 월말 종가로 전략 룰을 과거부터 다시 돌린 결과. DB에 적재되지 않은
  기간까지 이어진다. 월말 M까지의 가격만 보고 배분을 정하고 수익률은 다음 달 M+1로만
  매긴다(look-ahead 없음). 실제 운영 기록이 아니라 화면 계산이다.
- **Research 적재 구간** — 로컬 DuckDB에 실제로 적재된 적용월 사이의 성과.
  백필이 진행될수록 구간이 길어진다.
- **DB 대조** — 같은 적용월에서 저장 배분과 재현 배분이 같은지 맞춰 본다.
- **미래 경로 추정** — 과거 실제 월수익률을 무작위로 다시 뽑아(bootstrap) 향후 경로의
  분포를 그린다. 예측이 아니라 '지금까지의 변동폭이 이어진다면'이라는 가정의 산포도다.
- **전체 백테스트** — 월말 종가를 한 번만 받아 등록된 전략 전부를 같은 기간·같은 규칙으로
  재현하고 CAGR 순으로 나열한다.

### 판단에 영향을 주는 상태를 먼저 보여 준다

반복적인 원자료 표보다 사용자가 다음 행동을 결정하는 상태와 경고를 우선 표시한다.
원자료가 필요하면 owner가 제공하는 저장 행, provenance, Actions 로그로 이동한다.

| 상태 원천 | 화면 표시 | 무엇을 답하나 |
|---|---|---|
| `fundamentals.filing_processing.status` | terminal provenance 표시 | 숫자가 빈 게 정상 empty/unsupported인지 확인 |
| Discord `#운영-요약` 사건 카드 | 공시 카드 요약의 실패 안내 | 대차대조표·매핑·수집 실패의 원인과 재실행 경로 |
| `market.split_backfill_queue.status='pending'` | 공시 카드 요약 경고 | 과거 주가·주식수를 믿어도 되나 |
| `share_class_snapshots`의 클래스 품질 상태 | 공시 카드 요약 경고 | 배수의 주식수 기준이 모호한가 |
| GitHub Actions 실행 로그 | 매크로 운영 안내 | 오늘 수집이 실패했는지, 어떤 소스가 빠졌는지 |
| 13F `confidential_omitted` | 포트폴리오 상단 경고 | 도넛 합계가 실제 장부와 같은가 |

`execution.*`(주문·체결·계좌 스냅샷)와 `trading.*`(평가·승격·판단)은 저장 원장에
기록된 행만 표시한다. 현재 계좌 화면은 최신 계좌·보유 스냅샷을 읽고, 스냅샷에 없는
손익·환율은 추정하지 않는다.

모든 결과 컴포넌트는 `DB 저장 데이터`, `실시간 조회`, `화면 계산` 중 하나 이상을
표시한다. 연결 실패와 정상적인 빈 결과는 별도 상태로 유지하며, 숫자를 0이나 임의 값으로
대체하지 않는다. 기준 시각이 있는 경우 마지막 DB/외부 관측 시각을 함께 표시한다.

## 읽기 전용 안전 경계

- Supabase 접근은 `db.py`의 명시적 SELECT 함수만 사용한다. `insert`, `upsert`,
  `update`, `delete`, 상태 변경 RPC는 대시보드 코드에서 금지한다.
- “읽기 전용 분석 프리뷰”는 현재 조회한 데이터로 계산해 `st.session_state`에만 둔다.
  `investment_agent.trading.decision.portfolio_shadow`를 비롯한 저장 실행 경로를 호출하지 않는다.
- 룰 재현 백테스트는 `investment_agent.research.strategies.catalog`의 순수 계산 함수와
  `market.prices_daily`에서 읽은 일봉을 월말 기준으로 정규화한 저장 데이터만 쓴다.
  `investment_agent.research.strategies.etl`과 `investment_agent.research.strategies.db`(upsert 경로)는 import하지 않는다.
- 계좌·보유 화면은 로컬 런타임 SQLite의 `account_snapshots`에 저장된 관측 필드만 읽는다.
  브로커 원본(`raw_snapshot`)은 읽지 않는다. 스냅샷 생성과 브로커 조회는 execution 경계가
  소유하며, 대시보드는 브로커 클라이언트를 import하지 않는다.
- 뉴스 사용량 cap은 로컬 metadata-only SQLite 원장을 따른다. 기사 원문을 DB나
  파일에 저장하지 않는다. StockTwits는 명시적 권한 없이는 호출하지 않고 Reddit은 현재
  OAuth adapter가 없어 호출하지 않는다.
- 하네스 상태 파일은 JSON으로만 읽는다. 프로세스 종료·재시작·kill switch 변경 UI는 없다.
- `DASHBOARD_OFFLINE=1`이면 모든 DB/외부 네트워크 호출을 차단하고 실패 상태 UI만 검증한다.

## 실패와 품질 상태

데이터 loader는 `ok`, `empty`, `unconfigured`, `offline`, `blocked`, `error`를 구분한다.
오류 시 마지막으로 확인 가능한 기준 시각만 보여주며 샘플 티커, 가짜 가격, 난수 백테스트,
0원 계좌를 만들지 않는다. 13F 화면에는 최대 45일 지연 및 숏·파생·채권·해외·비상장
blind spot을 항상 표시한다. SEC GAAP 기반 숫자와 yfinance 조정 EPS는 별도 라벨로 구분한다.
